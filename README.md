## Язык программирования

SleekStack -- алгоритмический язык с C-подобным синтаксисом. Программа состоит из глобальных переменных и функций. Точка входа -- функция `main`.

```ebnf
program     ::= declaration*
declaration ::= "let" ident ("=" expression)? ";"
              | "def" ident "(" params? ")" block
params      ::= ident ("," ident)*
block       ::= "{" statement* "}"
statement   ::= declaration
              | block
              | "if" "(" expression ")" statement ("else" statement)?
              | "while" "(" expression ")" statement
              | "return" expression? ";"
              | expression ";"
expression  ::= assignment
assignment  ::= ident "=" assignment | equality
equality    ::= comparison (("==" | "!=") comparison)*
comparison  ::= term (("<" | "<=" | ">" | ">=") term)*
term        ::= factor (("+" | "-") factor)*
factor      ::= unary (("*" | "/") unary)*
unary       ::= "-" unary | call
call        ::= primary ("(" arguments? ")")*
arguments   ::= expression ("," expression)*
primary     ::= number | string | ident | "(" expression ")"
```

Семантика:

- вычисления строгие, слева направо;
- типы данных: 32-битное целое число и указатель на C-строку;
- строковый литерал хранится в памяти данных как последовательность кодов символов и `0`;
- видимость переменных: глобальная или функция; вложенные блоки не создают отдельную область видимости;
- встроенные функции:
    - `print(x)` / `puts(x)` -- вывести строковый литерал как C-строку, числовое выражение как одно значение;
    - `putc(x)` -- вывести одно значение в порт вывода;
    - `getc()` -- прочитать одно значение из порта ввода;
    - `ei()`, `di()`, `iret()` -- инструкции управления прерываниями.

## Организация памяти

Архитектура памяти -- Гарвардская:

- память команд содержит байтовый машинный код;
- память данных содержит 32-битные машинные слова;
- память команд и память данных адресуются независимо;
- адрес `0` в памяти данных зарезервирован под вектор обработчика прерывания;
- глобальные переменные, локальные переменные функций и строковые литералы размещаются статически в памяти данных;
- стек данных и стек возвратов являются внутренними структурами процессора.

Memory-mapped I/O:

| Адрес | Назначение |
|:------|:-----------|
| `31998` | порт ввода |
| `31999` | порт вывода |

Строки имеют формат `cstr`: один символ на одно машинное слово, после последнего символа записывается `0`.

## Система команд

Система команд -- стековая. Арифметические операции берут операнды со стека и кладут результат на стек. Команды `load` и `store` работают с памятью данных, включая memory-mapped I/O.

### Набор инструкций

| Инструкция | Аргумент | Тактов | Описание |
|:-----------|:---------|:------:|:---------|
| `literal` | value | 1 | положить непосредственное значение на стек |
| `load` | addr | 2 | прочитать `mem[addr]` на стек |
| `store` | addr | 2 | записать вершину стека в `mem[addr]` |
| `stack_to_a` | - | 1 | перенести вершину стека в регистр адреса `A` |
| `a_load` | - | 2 | прочитать `mem[A]` на стек |
| `a_load_+` | - | 3 | прочитать `mem[A]` на стек и увеличить `A` |
| `a_store` | - | 2 | записать вершину стека в `mem[A]` |
| `add`, `sub`, `mul`, `div`, `mod` | - | 2 | арифметика над двумя верхними элементами стека |
| `increment`, `decrement` | - | 2 | изменить верхний элемент стека на 1 |
| `inv`, `and`, `xor`, `or`, `lshift`, `rshift` | - | 2 | битовые операции |
| `drop` | - | 1 | снять вершину стека |
| `dup` | - | 1 | продублировать вершину стека |
| `over` | - | 1 | поменять местами два верхних элемента |
| `jmp` | addr | 1 | безусловный переход |
| `if` | addr | 2 | переход, если значение равно 0 |
| `mif` | addr | 2 | переход, если значение неотрицательное |
| `nif` | addr | 2 | переход, если значение не равно 0 |
| `call` | addr | 1 | вызов подпрограммы |
| `return` | - | 1 | возврат из подпрограммы |
| `ei`, `di` | - | 1 | разрешить/запретить прерывания |
| `iret` | - | 2 | возврат из обработчика прерывания |
| `halt` | - | 0 | останов |

### Кодирование инструкций

Кодирование определено в модуле [isa.py](./isa.py).

Инструкции без аргумента занимают 1 байт:

```text
┌─────────┐
│ opcode  │
└─────────┘
```

Инструкции с аргументом занимают 5 байт:

```text
┌─────────┬─────────────────────────────────┐
│ opcode  │ signed 32-bit big-endian arg    │
└─────────┴─────────────────────────────────┘
```

Пример строки листинга:

```text
0x0005-0x0009 - 0x0600000002 - literal 2
```

## Транслятор

Интерфейс командной строки:

```shell
python translator.py <input_file> <target_file>
```

Реализовано в модуле [translator.py](./translator.py).

Выходные файлы:

- `<target_file>` -- бинарный машинный код;
- `<target_file>.lst` -- листинг памяти данных и памяти команд;
- `<target_file>.config.json` -- конфигурация модели: размеры памяти, адреса портов, образ памяти данных;
- `<input_file>.ast` -- дамп AST.

Этапы трансляции:

1. Лексический анализ.
2. Рекурсивный спуск по грамматике языка.
3. Статическое размещение глобальных переменных, локальных переменных и строк.
4. Генерация стекового машинного кода.
5. Разрешение адресов переходов и вызовов.
6. Сериализация бинарного кода и отладочного листинга.

Пример:

```shell
python translator.py examples/euler6.ss out.bin
```

## Модель процессора

Интерфейс командной строки:

```shell
python machine.py <code.bin> <config.json> [schedule.txt] [log.txt] [--log log.txt]
```

Реализовано в модуле [machine.py](./machine.py).

Вывод:

- stdout: итоговый буфер вывода и количество тактов;
- `log.txt`, если указан: журнал каждого такта процессора.

Формат расписания ввода:

```text
<tick> <token>
```

где `tick` -- такт появления значения на входном порту, `token` -- символ или числовой код. При наступлении такта порт ввода защёлкивает значение и выставляет запрос прерывания.

### DataPath

```text
                         command immediate
                                │
                                ▼
                           ┌────────┐
                           │  MUX   │◄──────────────┐
                           └───┬────┘               │
                               │                    │
                               ▼                    │
                         ┌──────────┐               │
                         │ data     │               │
                         │ stack    │────────┐      │
                         └──────────┘        │      │
                              │ pop          │      │
                              ▼              │      │
            ┌────────┐   ┌────────┐          │      │
            │ return │◄──│  ALU   │◄─────────┘      │
            │ stack  │   └────────┘                 │
            └────────┘        │                     │
                              ▼                     │
                         ┌──────────┐ addr ┌─────────────┐
                         │ register │─────►│ data memory │
                         │    A     │      │  + MMIO     │
                         └──────────┘      └─────────────┘
                                                │
                                                └────────► output buffer
```

Регистры и состояния:

- `A` -- указатель для косвенной адресации строк и команд `a_load`, `a_load_+`, `a_store`;
- `AR` -- адресный регистр текущего обращения к памяти данных;
- `ALU.left`, `ALU.right`, `ALU.out`, флаги `Z` и `N`;
- стек данных `DS` и указатель `SP`;
- стек возвратов `RS` и указатель `RSP`;
- входной порт и буфер вывода.

Сигналы DataPath реализованы методами класса `DataPath` и вызываются только из ControlUnit:

- `latch_a`, `latch_ar`;
- `latch_input_port`;
- `push_data`, `pop_data_now`, `dup_data`, `swap_top_two`;
- `push_return`, `pop_return_now`;
- `read_memory`, `write_memory`.

Память данных является однопортовой: за один такт допускается либо чтение, либо запись.

### ControlUnit

```text
          ┌─────────────────────────────┐
          │        command memory        │
          └──────────────┬──────────────┘
                         │ opcode/arg
                         ▼
     ┌──────┐       ┌─────────┐       ┌──────────────┐
     │  PC  │◄──────│ decoder │──────►│ signal logic │
     └──────┘       └─────────┘       └──────┬───────┘
        ▲                                     │
        │                                     ▼
        │                              ┌────────────┐
        └──────────────────────────────│  DataPath  │
                                       └────────────┘
```

ControlUnit -- hardwired. Он содержит:

- `PC` -- счётчик команд;
- `IR_OPCODE`, `IR_ARG` -- декодируемая инструкция;
- `tick` -- текущий такт;
- `step` -- микрошаг многотактовой инструкции;
- `IE`, `pending_interrupt`, `in_interrupt`, `entering_interrupt`, `int_step` -- состояние системы прерываний.

Модель работает с точностью до такта. Каждый такт состоит из двух фаз:

1. ControlUnit декодирует инструкцию или шаг входа в прерывание, вычисляет сигналы и значения на входах регистров.
2. Все запланированные защёлки независимых регистров фиксируются одновременно.

Это означает, что две независимые защёлки могут сработать за один такт, но зависимые операции увидят новое значение только на следующем такте.

Прерывания:

- адрес `0` памяти данных -- вектор обработчика;
- при входе в прерывание аппаратно сохраняются `PC` и `NZ` в стек возвратов;
- затем из `mem[0]` читается адрес обработчика и загружается в `PC`;
- `iret` восстанавливает `NZ`, `PC`, разрешает прерывания и снимает флаг `in_interrupt`;
- новое прерывание во время обработки остаётся отложенным до возврата.

Журнал такта содержит `TICK`, `PC`, `STEP`, инструкцию, `A`, `AR`, флаги, состояние прерываний, стек данных, стек возвратов, действие памяти, защёлкнутые регистры и буфер вывода.

Модель использует [isa.py](./isa.py) как единый источник кодов операций и формата бинарного машинного кода.

## Тестирование

Golden tests находятся в [tests/test_golden.py](./tests/test_golden.py), конфигурации -- в [golden](./golden).

Покрытые алгоритмы:

- [hello](./golden/hello.json) -- печать `Hello, world!`;
- [cat](./golden/cat.json) -- посимвольный ввод через `trap` и вывод входных данных;
- [hello_user_name](./golden/hello_user_name.json) -- запрос имени и вывод `Hello, <name>!`;
- [sort](./golden/sort.json) -- чтение трёх числовых символов и вывод их в отсортированном виде;
- [double_precision](./golden/double_precision.json) -- демонстрация двухсловной арифметики;
- [euler6](./golden/euler6.json) -- алгоритм варианта, Project Euler problem 6;
- [features](./golden/features.json) -- функции, вызовы, возврат и ветвление.

Каждый golden test проверяет:

- исходный алгоритм через SHA-256 исходного файла;
- бинарный машинный код через SHA-256;
- образ памяти данных и конфигурацию машины через SHA-256;
- вывод симулятора;
- количество тактов;
- репрезентативные фрагменты журнала процессора.

Запустить тесты:

```shell
python -m py_compile translator.py isa.py machine.py
python -m unittest tests.test_golden -v
```

Пример ручного запуска:

```shell
python translator.py examples/euler6.ss out.bin
python machine.py out.bin out.bin.config.json --log out.log
```
